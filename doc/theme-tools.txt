CONFIGURATION                                         *theme-tools-config*
>
  require("theme_tools").setup({
    catppuccin = { transparent_background = true }, -- passed to Catppuccin setup
    install = {
      root = vim.fn.stdpath("data") .. "/theme-tools/themes",
      timeout = 30000, -- total download timeout in milliseconds
    },
    -- With no themes list, discover defaults to true. With a list, it is false.
    themes = {
      "theme-tools-mocha",         -- included independent personal theme
      "catppuccin-mocha",
      {
        name = "day",               -- stable ID used by commands and state
        label = "Daylight",         -- optional picker label
        colorscheme = "morning",    -- defaults to name
        background = "light",       -- optional: light or dark
        before = function(theme)    -- optional: runs before every application
          -- Configure or load a theme plugin here if needed.
        end,
      },
    },
    discover = false,               -- append installed schemes to explicit list
    default = "theme-tools-mocha",   -- used if no saved, available ID exists
    persist = true,
    state_file = vim.fn.stdpath("state") .. "/theme-tools/selection.json",
    picker = { backend = "builtin", width = 52, height = 12, border = "rounded" },
  })
<
Catppuccin is a built-in managed source, downloaded from its official Git
repository at the commit pinned in theme_tools.providers.catppuccin. The first
Catppuccin selection installs it if missing, adds it to runtimepath and passes
the catppuccin table to require("catppuccin").setup(). No separate Catppuccin
plugin spec is needed. ColorSchemePre also supports direct :colorscheme calls.
Use catppuccin=false to disable both managed installation and configuration.
Sources initialize once per setup; selecting another theme skips them entirely.
Register managed theme names explicitly to list them before their source loads.
:ThemeToolsInstall explicitly installs and reconfigures the managed source.

theme-tools-mocha is an independent personal theme derived from Mocha with a fixed
set of integrations, transparent backgrounds and personal highlight overrides.
Its generated colors file applies highlights directly; no Catppuccin modules,
setup, integration detection, runtime compilation or cache validation run.
Catppuccin options do not affect it. Edit lua/theme_tools/mocha/palette.lua and
groups/*.lua, then run from the repository:
>
  nvim --headless -u NONE -l scripts/build_mocha.lua
<
Commit the source and generated colors/theme-tools-mocha.lua together. Generation
is deterministic, offline and independent of upstream. vim.loader can cache the
generated Lua source as local bytecode. The palette is also available through
require("theme_tools.mocha.palette") for statusline components. See the README
and LICENSE.catppuccin for provenance and maintenance details.

When Lazy and vim.loader are active, integration detection uses Lazy's existing
plugin inventory plus native vim.pack packages. Catppuccin receives resolved
integration options with its own auto-detection disabled for that setup. Explicit
integration settings retain upstream precedence. The inventory is read on each
setup; plugin/profile changes are not cached. Pckr, disabled module caching and
unrecognized environments retain the normal upstream detector. Catppuccin's own
compiled theme cache and ColorScheme events remain in use.

The first download requires Git and network access. Subsequent startups reuse
the installed revision without invoking Git or fetching. Source checkouts live
under install.root/catppuccin/<commit>. A temporary directory is checked out and
verified before it is published. Failed downloads clean up only their own
temporary directories; an incomplete existing target is reported, not overwritten.
The fixed revision is updated by updating theme-tools and restarting Neovim;
no background updater runs.
The install timeout bounds the complete Git operation. Other installed themes
remain usable if a managed download fails. :ThemeToolsInstall retries downloads.

Themes may be strings or tables. Names must be nonempty without whitespace;
labels are for display only. Duplicate names replace the earlier definition
while preserving its position. Width and height are maximum cell counts, clamped
to the current screen. Border uses nvim_open_win() border syntax.
The four explicit Catppuccin variants infer their light/dark background unless
overridden. This prevents Catppuccin's remembered flavour from mistaking a later
selection for a background-mode toggle after an independent theme was active.

Set picker.backend="selection_tools" to use selection-tools.nvim (requires its
on_change API). It inherits that plugin's compact select layout, matching and
keys. picker.selection accepts per-picker layout, matcher and keys overrides.
The active theme appears first. Width/height/border above apply to the builtin
backend. Both backends share preview, persistence and cancellation semantics;
selection-tools owns selection, window lifecycle and navigation for its backend.
Resume, multiple selection and file-opening/export actions are disabled for
theme pickers so callbacks remain tied to the current preview session.

setup() replaces earlier configuration and registrations, cancels an open picker,
and restores an available saved ID, falling back to default. With neither, the
current colorscheme stays active. persist=false disables both reading and writing
state. Corrupt state is ignored with a warning. Unavailable saved IDs are ignored.
If a saved theme fails to load, its error is reported and the prior palette is
restored. State stores only the theme ID; it never stores or evaluates Lua code.

Before callbacks can call require("lazy").load({plugins={"theme-name"}}) or a
theme's setup() if needed. Colorschemes on runtimepath need no adapter. Explicit
themes can be autoloaded by lazy.nvim even before they appear in discovery.

API                                                   *theme-tools-api*
>
  local themes = require("theme_tools")
  themes.pick()                     -- open a searchable live preview
  themes.install()                  -- ensure configured managed themes are loaded
  themes.close()                    -- cancel preview; safe to repeat
  themes.set("catppuccin-mocha")     -- apply and save
  themes.next()                     -- apply next, wrapping
  themes.prev()                     -- apply previous, wrapping
  themes.current()                  -- matching registered ID, or nil
  themes.list()                     -- copied list in picker/cycling order
  themes.register({ name = "night", colorscheme = "habamax" })
<
install(), pick(), set(), next() and prev() return true on success or nil, error
on failure.
Commands report these errors with vim.notify(). Failed previews cannot be
confirmed. Saving errors warn while keeping the successfully applied theme.
close() is also called before direct switching/cycling. register() affects the
next picker opening; it does not modify an already open picker's list.

After a confirmed selection or successful direct application, this event fires:
>
  vim.api.nvim_create_autocmd("User", {
    pattern = "ThemeToolsChanged",
    callback = function(event)
      -- event.data: {name, colorscheme, background}
    end,
  })
<
Normal ColorScheme events run during preview and restoration, so existing
highlight integrations follow the preview. ThemeToolsChanged is emitted only
when committing a selection (including startup restore/default), never merely
for previews or cancellation. Use an adaptive statusline theme if you want it
to follow colorscheme changes rather than holding a fixed theme palette.

BEHAVIOR                                              *theme-tools-behavior*

Cancellation restores the opening colorscheme, 'background', global highlight
definitions (including manual overrides), g:colors_name and g:terminal_color_0
through g:terminal_color_15. Failed loads restore the last successful palette.
No state is saved while browsing, filtering, resizing or cancelling.

This restoration covers colors, not arbitrary side effects from theme scripts,
before callbacks or ColorScheme autocommands. Avoid callbacks that mutate buffers
or unrelated editor options. Existing terminal jobs may retain their own colors.
The picker exits Insert mode when it closes and leaves source text unchanged.

The plugin loads no themes or mappings just from require("theme_tools"). Normal
plugin loading installs :ThemeTools, :ThemeToolsNext, :ThemeToolsPrev and
:ThemeToolsInstall. setup() also installs them and is required on startup to
restore saved choices.
